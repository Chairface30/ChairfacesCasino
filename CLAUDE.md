# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

World of Warcraft addon ("Chairface's Casino") providing multiplayer casino games — Blackjack, 5 Card Stud Poker, Texas Hold'em, High-Lo, Death Roll, Bingo, Roulette, Liar's Dice, and the Chair's Cup derby — over the WoW addon channel, plus a solo arcade (Slots, Video Poker) played on a persistent fake-credit balance in `Arcade.lua` (no networking, no leaderboard, plain `math.random`; deliberately outside the `Lobby.gameList` one-game-at-a-time gating). Pure Lua, no build system: WoW loads the files listed in `Chairfaces Casino.toc` in order. Test by copying/symlinking the folder into `World of Warcraft/_retail_/Interface/AddOns/` and reloading in-game (`/reload`).

Supported client interface versions are declared in the `.toc` header (Classic Era through Retail). When adding APIs, check they exist across targets or guard with `if ... then`.

## Slash commands (in-game)

- `/cc` or `/casino` — open lobby
- `/hilo <max> [timer]` — quick-host High-Lo
- `/cc debts` (or `debt`/`ledger`/`tab`) — session settle-up ledger window
- `/cc fakeplay` (or `fun`) — toggle fake play: games this client hosts record no debts
- `/cc lfg` (or `finder`/`find`/`lft`) — Table Finder: LFG-style board to list yourself hosting/seeking and browse others
- `/cc db` — toggle hidden test mode (gated by `TestMode:CanUseDebugMode()` — only specific character names)
- `/cc zep <displayID>|file <fileID>|next|prev|face|scale|off` — hidden (same gate as `/cc db`): audition zeppelin models live over the Crash window's hand-drawn ship; the known-bad transport zeppelin m2 hard-crashes the client, so the last ID typed before a CTD is the culprit
- `/cc test add|remove|deal|hit|stand|...` — test-mode harness for solo play with fake players (`/cc test debt add|pay|list|wipe` exercises the debt ledger)
- `/cc test arcade grant <name> <n>` — hidden (same gate as `/cc db`): comp any character n arcade credits out of house money. Also reachable from the purple **GRANT** button on the Slots cabinet / Video Poker window, which is only *built* for allow-listed characters. The wire is a `GRANT|<n>` whisper on the existing `CCArcade` gift prefix and the RECEIVER re-checks the sender against `TM:IsAuthorizedName`, so a forged grant from anyone else is dropped (same both-ends pattern as the leaderboard's `CLEAR_DB`)

## Architecture

Single global namespace `ChairfacesCasino` (aliased `BJ` everywhere). Every module attaches itself as `BJ.ModuleName = {...}`. Load order in `.toc` matters — Core → Libs/infra → per-game State → per-game Multiplayer → UI.

File layout (since 2.4.2; the flat root was reorganized, load order unchanged): `Core.lua` bootstraps at the root; cross-cutting infrastructure lives in `Core\` (GameComm, StateSync, DebtLedger, TableFinder, ...); each game's State+Multiplayer pair lives in `Games\<Game>\` (Blackjack keeps its historical `GameState.lua`/`Multiplayer.lua` names inside `Games\Blackjack\`; the derby pair is `Games\Derby\`; the solo arcade is the single `Games\Arcade.lua`); all windows including `LeaderboardUI.lua` are under `UI\`. Files find each other through the shared namespace, never by path — moving a file only means updating its `.toc` line (and the `tests/*.py` load paths for the three tested modules). Media is grouped too: `Sounds\Trixie\` (voice), `Sounds\Arcade\` (slot machine), `Sounds\Derby\`/`Sounds\Kenney\`, shared one-offs at the Sounds root; `Textures\Crash\` (zeppelin/tower/trees/mountains), `Textures\Poker\` (BB/SB/DEALER buttons), `Textures\Arcade\`, `Textures\Widgets\` (shared UI icons), plus the existing `cards*/dealer/chips/dice` folders — unlike Lua, media IS referenced by path strings, so moving a media file means rewriting its references (several are dynamic prefix concatenations: `reel_stop`..n, `trix_poke`..n, `Textures\Crash\" .. kind.file`, the card deck paths).

### Per-game pattern

Each game (Blackjack, Poker, HiLo) has two files:

- `<Game>State.lua` — pure logic: deck/shoe, phases (`PHASE.IDLE/WAITING/DEALING/...`), scoring, history. Persists via `LoadHistoryFromDB` / saved vars (both built on `BJ.GameHistory`). Game-specific constants live here; card constants/shuffling come from `BJ.CardLib`. The two poker games embed `BJ.PokerEngine` (constants, deck, betting rounds, actions, hand evaluation, showdown/settlement, history) and keep only their rule differences: `PokerState.lua` has ante + bring-in/highest-visible-hand ordering; `HoldemState.lua` has blinds, dealer button, community cards, and best-5-of-7 evaluation via a `GetShowdownEval` override. Hold'em also has **tournament mode** (`PS:StartTourney`; engine hooks are shared in PokerEngine and guarded by `self.tourney`): the table locks to a gold buy-in, everyone starts with the same chip stack and blinds are CHIPS, joins are refused after the first deal (and use a separate `TOURNEY_JOIN` message so pre-2.4.3 clients can't sit down), betting each hand is capped at the shortest stack (table stakes — every bet is callable, so the single-pot settlement never needs side pots), busted/forfeited stacks lose their seat, and when one stack holds everything the champion collects every buy-in through the debt ledger (per-hand recorders are suppressed — chips aren't gold). Chip stacks are deterministic from the broadcast settlements, so clients track them without extra sync; StateSync carries the tournament block for mid-tournament rejoins. Tournaments are deliberately **one table only** (a large one — up to the 10-seat max; a multi-table director system was built and then removed as too complex — may be revisited if there's demand). The prize pool (every buy-in; forfeited buy-ins stay in) is **winner-take-all** — the champion collects everything in one host-recorded zero-sum debt entry (a 50/30/20 top-three split shipped in 2.5.0 and was dropped in 2.5.2: it was sized for multi-table fields; `t.eliminated` still tracks finish order for the elimination display and StateSync). Chip-pile visuals (`UI/ChipPot.lua`) render amounts as denomination chip stacks with ONE global `CP.SCALE` (test-mode `/cc chipscale <n>` tunes it live); pots draw to the RIGHT of the pot box, tournament seats show each player's stack under their cards. Crash also plays a random goblin panic line on every bail-out (fileID tiers ending in the guaranteed vanilla goblin vocals). Tests: `tests/holdem_tourney_test.py`.
- `<Game>Multiplayer.lua` — AceComm network layer: hosts broadcast table-open/deal/sync, clients send actions (ANTE/HIT/STAND/etc.). Each game uses its own AceComm prefix (e.g. `CCBlackjack`, `CCPoker`). Each module calls `BJ.GameComm:Embed(module, config)` at the top of the file to pull in the shared plumbing (send/receive, roster watching, host recovery, countdown, turn timer), then defines its message handlers plus the hooks GameComm dispatches to: `RouteMessage`, `OnCountdownComplete`, `ShouldRunTurnTimer`, `OnTurnTimeout`, `ResetState`. Later `function Module:X()` definitions override the embedded defaults (High-Lo replaces the whole recovery flow with a permanent host transfer this way).

Blackjack is the exception that proves the rule: its state lives in `GameState.lua` (not `BlackjackState.lua`) and its network in `Multiplayer.lua`. Treat `GameState`/`Multiplayer` as the Blackjack pair.

Death Roll and High-Lo are built on real server-verified `/roll`s captured from `CHAT_MSG_SYSTEM` (parsed by `BJ:ParseRoll` in `Core.lua`: `"^(.+) rolls (%d+) %(1%-(%d+)%)$"`, realm dropped — WoW Forever names are always a first name and a surname, "Chairface Chippendale", so never match a name with `%S+`), so every client updates state from chat directly and the host's broadcasts are redundancy. Crash is a pot-based game of chicken: everyone antes into the pot, the zeppelin always explodes (RISING per-tick hazard past the climb-out — `HAZARD + HAZARD_RAMP*tick`, so deaths cluster erratically low-mid, ~7% clear 600m, the 1000m cap is a ~0.1% spectacle). Exception: when every rider has jumped, she makes an on-screen escape run for the right edge — riders are already safe, but the flight ticker keeps running, so a crash tick landing during the run explodes her on screen anyway (the close call); only if she survives `CM.FLYAWAY_EXIT_SECS` does the host end the round as a FLY-AWAY (`CS.flyAway`, CRASH wire field 4) with the crash point never displayed (the reveal still rides the wire for verification; settlement identical either way). The pilot/host MAY ride their own ship (host joins locally + broadcasts JOIN_OK; the fate exists on their machine but is never displayed — a trust convention, same spirit as fake play), and the last rider to jump before the explosion takes the pot (tick ties split; nobody jumping pushes). The pilot/host runs the commit-reveal but can't ride (they know the fate) and banks nothing; a mid-flight disconnect does NOT void a rider's ante (a refund would beat losing — they ride on, and their auto-jump can still win). Changing `CrashPointFromSeed` breaks crash-table consistency with older sub-versions even though the wire still parses. Tests: `tests/crash_test.py`. Bingo cards and its draw order are deterministic from a shared seed (`BingoState:GenerateCard` / `BuildDrawPool`), so all clients render and daub every card identically and a returning host resumes the draw exactly. The lobby's game-gating goes through the `Lobby.gameList` registry (`UI/Lobby.lua`) — a new game needs one entry there plus its lobby button.

UI is split per game under `UI/` (`MainFrame`=Blackjack, `PokerFrame`, `HiLoFrame`) plus shared `Lobby`, `Cards`, `Buttons`, `Animation`, `HostPanel`, `Settlement`.

### Cross-cutting infrastructure

- **GameComm.lua** — shared multiplayer plumbing embedded into every `<Game>Multiplayer` module (see per-game pattern above): `|`-delimited serialize/deserialize (empty-field-preserving; wire format must stay stable), AceComm send/whisper with compression and StateSync version injection, incoming-message preamble with StateSync routing, roster watching, the 2-minute host-disconnect recovery (temp host, popup, void), pre-deal countdown, and the 120-second turn timer (sized so a disconnected client can reconnect before being auto-folded).
- **PokerEngine.lua** — shared poker logic embedded by `PokerState`/`HoldemState` via `BJ.PokerEngine:Embed(module, config)`; later `function Module:X()` definitions override the embedded defaults.
- **CardLib.lua** — shared card constants (`SUITS`, `BLACKJACK_RANKS/_RANK_VALUES`, `POKER_RANKS/_RANK_VALUES`) and `CreateShuffledDeck(seed, numDecks, ranks, suits)`. The seeded PRNG and Fisher-Yates order must stay byte-identical across versions — clients rebuild decks from the host's seed.
- **GameHistory.lua** — shared save/load/trim for the per-game "last 5 games" logs in `ChairfacesCasinoSaved`.
- **DebtLedger.lua** — cross-game session debt tracker (prefix `CCDebtLedger`, UI in `UI/DebtsFrame.lua`, lobby "Debts" button, `/cc debts`, and a `UI.Debts:AttachDebtsIcon` shortcut on every game window — it replaced the old per-game session-leaderboard icon, whose `LBUI:ToggleSession` frames are now unreachable from the UI). Every game feeds it from the same host-gated spot where it calls `Leaderboard:RecordHandResult` — banked games (Blackjack/Roulette/Derby) record explicit player↔host pairs, pot games (both pokers, Bingo, Crash) call `RecordNets` (deterministic biggest-loser→biggest-winner decomposition of zero-sum nets), duel games record loser→winner. Balances net per player pair across games, persist in `ChairfacesCasinoDB.debtLedger` until paid or forgiven (no expiry), and are settled by trade-window detection (both participants apply locally from trade events; only the payer broadcasts `PAY`; payments cap at the debt — overpay is a gift, never a credit). The per-row **Settle** button (`DL:SettleWithTrade`) finds the creditor's group unit, `InitiateTrade`s them, and pre-fills the exact gold owed via the `autoFill` handoff to `OnTradeShow`. **Addons cannot stage trade gold on modern clients** — `SetTradeMoney` is `AllowedWhenUntainted` (silently ignored from addon code, hardware event or not; anti-scam hardening) and the money-input widgets reject addon writes too (`MoneyInputFrame_SetCopper` and direct `SetText` both threw "bad self"). Don't try to bypass this. The fill attempts `SetTradeMoney` once (free; works on any client where it isn't blocked) and VERIFIES via `GetPlayerTradeMoney`; when refused it shows the "Settle: type Xg" banner pinned above the trade window (`DL:ShowTradeBanner`, also shown on any manual trade with a creditor) plus a chat line, and the trade-completion detection clears the tab from whatever was actually typed. `FORGIVE` is only honored when the sender is the creditor. **Fake play** (`/cc fakeplay`, `db.settings.fakePlay`) gates `RecordDebts` host-side: fun games record nothing and broadcast a one-line `FUN` notice instead — and since settlement gating (see Leaderboard), fun games no longer reach the shared leaderboard either (only the local myStats panel). The ledger notifies the leaderboard about every pair-balance event: `RecordDebts` reports each round's pairs via `LB:OnDebtsRecorded` (fake rounds report `fakePlay=true`), and `ApplyDebt`/`ApplyPayment`/`ApplyForgive`/`HandleSyncFull` fire `NotifyPairState` when a pair touches zero so pending leaderboard hands graduate (or are voided by forgiveness). The toggle is surfaced as a checkbox next to **every game's host button** (all 10 games + the Debts window) via `UI.Debts:AttachFakePlayCheck`; every copy registers in `DF.fakeChecks` and stays in sync through `NotifyChanged → UpdateFakePlayChecks`. Late joiners `SYNC_REQ`; merge is newest-`updated`-wins per pair, and paid-off pairs are kept ~7 days as zero-balance tombstones so stale peers can't resurrect settled debts. Tests: `tests/debt_test.py` (multi-runtime lupa simulation).
- **StateSync.lua** — versioned sync with gap detection. Every state-changing broadcast carries a version; clients that detect a gap request a full-state dump (whisper). Also handles host discovery (`CCDiscover` prefix) and "am I playing?" rejoin-on-reload flow. Each game tracks its own version counter in `SS.versions`. Per-game dispatch goes through the `SS.games` registry (populated automatically by `GameComm:Embed`) plus `SS.stateHandlers` (build/apply/onSynced serialization handlers at the bottom of the file) — adding a game means one `Embed` call and one `stateHandlers` entry, not editing a dozen if/elseif chains.
- **SessionManager.lua** — global lock preventing two games running simultaneously in the same group. `Lobby:IsAnyGameActive()` is the gate; check it before hosting.
- **Multiplayer version gating** — `BJ:OnPeerVersion` / `ShowPendingVersionWarning` compare peer versions seen over the wire; warning is deferred until the user opens a casino window. Compatibility is by **major.minor only** (`BJ:VersionsCompatible`): sub-versions like `2.3.1` vs `2.3.4` are wire-compatible and must NOT trip the mismatch warning or join rejections — only a major.minor bump (`2.3` → `2.4`) signals incompatibility. Iterate with `2.3.x` sub-versions freely; **do not bump `BJ.version`/`## Version` to a new major.minor without explicit permission.** Bump `BJ.version` in `Core.lua` *and* `## Version` in the `.toc` together.
- **Compression.lua** — optional LibCompress wrapper for large payloads and for XOR-obfuscated saved-data encoding. Falls back to plaintext if LibCompress absent.
- **Leaderboard.lua / LeaderboardUI.lua** — session + all-time stats, encrypted (player-salted XOR + checksum) in `ChairfacesCasinoSaved`. Separate AceComm prefix `CCLeaderboard`. Sync is duplication-proof by construction (**per-recorder buckets**, a grow-only counter CRDT): every hand is recorded by exactly one machine (the game's host — all `RecordHandResult` call sites are host-gated), lands in that recorder's own bucket under the player's row, and each machine only ever ADDS to its own buckets — everyone else's copies are replicas replaced wholesale when strictly newer (bucket `games` count is an exact version, not a heuristic; ties break deterministically). A row's displayed total is the sum of its buckets, so replays/rebroadcasts/out-of-order digests are always no-ops. **Settlement gating**: a hand does NOT hit the shared board at game settlement — it stages (`StageHand`), binds to the debt-ledger pair(s) its gold flows through (`FinalizeStagedHands` at flush, married to `RecordDebts` via `OnDebtsRecorded`; derby↔chairscup key alias), and graduates into the recorder's bucket only when every watched pair's balance clears (trade payment OR later results netting it square). Forgiven pairs VOID their pending hands, FREE PLAY rounds are discarded, zero-net hands (push/participated) commit immediately, and a dead/silent ledger fails OPEN (counts like pre-gating). Pending hands persist in `ChairfacesCasinoDB.lbPending` (plaintext, beside the ledger); graduation is recorder-local and rides the normal flush — no wire changes. Session board and myStats stay live. Tests: `tests/leaderboard_pending_test.py`. Broadcasts batch 0.5s after settlement (`B3` own-buckets blob, sender-validated); anti-entropy via digest (`D3` on roster change/manual sync → peers whisper back only strictly-newer buckets, `R3`, 30s per-sender throttle). Session boards use the same scheme with the recorder's session `start` in the version pair (fresh party session supersedes stale buckets). Pre-bucket rows migrate once into frozen `LEGACY:<owner>` buckets (same id everywhere → converges, never stacks). Legacy messages (`AT_UPD`/`STATS_BC`/`SESS_UPD`) are still EMITTED for pre-bucket clients but never ingested — blended accumulator totals can't be deduplicated, so in mixed groups upgraded clients only count hands recorded by upgraded hosts. Realm-wide sync means strangers can whisper payloads, so ingest is hardened: every incoming bucket is type/bounds-sanitized (`sanitizeBucket` — non-numbers, non-finite, absurd counts, and unknown game keys are dropped), `R4` digest replies are only ingested within 10 min of us actually sending a digest (`DigestPending`), and `CLEAR_DB` is honored only from TestMode-allowlisted senders (`TM:IsAuthorizedName`). Saves are debounced (`QueueSave`, 10s + PLAYER_LOGOUT flush) because a full save re-encrypts the whole board. The realm HELLO queue holds at most one entry (it's idempotent; stacking them spammed the channel on the next hardware flush). The board's Reset button clears only local `myStats` — shared rows have no tombstones, so a local row delete would just resurrect from peers' replicas; only a season bump truly clears the board. Tests: `tests/leaderboard_sync_test.py` (multi-runtime relay), `tests/leaderboard_season_test.py` (season epoch + realm reconcile + ingest guards). `myStats` (pushes/bestWin/worstLoss panel) stays local-only and no longer mirrors into rows.
- **TableFinder.lua / UI/TableFinderFrame.lua** — LFG board (`/cc lfg`, lobby "LFG" button, casinolink `finder`): players list themselves as hosting/seeking a game with stakes + note; rows offer Whisper/Invite. Listings are ephemeral (15-min TTL backstop, 4-min heartbeat, not saved) and live in `TF.listings` keyed by short name. Transport: GUILD + PARTY/RAID addon messages (prefix `CCTableLFG`) plus the shared hidden `ChairfaceCasino` chat channel (mark `CCLFG7`) for realm-wide reach — channel sends are hardware-gated, so they queue until a finder button click flushes them (`TF:FlushChannelQueue`). TableFinder owns joining the channel at login (the retired events calendar used to), and the channel doubles as presence: a member's `CHAT_MSG_CHANNEL_LEAVE` (logout/disconnect/alt-f4) drops their listing immediately. `REQ` makes listed players re-announce by staggered whisper (60s reply throttle). GameComm also plays a subtle `coin_drop.ogg` chime (`GC:PlayTableOpenChime`, 60s per-game throttle, NOT gated on a window being open) whenever any game's TABLE_OPEN broadcast arrives, so idle addon users hear tables opening. Tests: `tests/finder_test.py`.
- **EscapeHandler.lua** — centralizes Escape-key window-closing across all frames.
- **MinimapButton.lua** — LibDBIcon-style button; size/scale persisted in `BJ.db.settings`.
- **TestMode.lua** — fake players and auto-play for solo testing. Obfuscated gate (`V` table keyed by hashed character names) restricts who can enable it.

### Saved variables

Two SVs, both declared in the `.toc`:
- `ChairfacesCasinoDB` — settings + stats (plaintext). Defaults in `Core.lua`; `OnAddonLoaded` merges missing keys so updates don't wipe user prefs.
- `ChairfacesCasinoSaved` — encrypted payload (leaderboard, poke-chance, intro-shown flag). Go through `BJ.Compression:EncodeForSave` / `DecodeFromSave`.

### Init flow

`Core.lua` registers `ADDON_LOADED` (→ load SVs) and `PLAYER_LOGIN` (→ initializes every module in a fixed order: HostSettings → SessionManager → StateSync → Leaderboard → DebtLedger → per-game Multiplayer → UI → MinimapButton → EscapeHandler → history loaders). Cleanup on `PLAYER_LOGOUT` must avoid network calls (protected-function errors); it only cancels timers and resets local state.

**ADDON_LOADED gotcha:** WoW passes the folder name ("chairfaces casino", with space) — the hardcoded `BJ.name` ("ChairfacesCasino") never matched, so for all of 2.x `OnAddonLoaded` silently never ran and `BJ.db` was nil until some module's fallback touched it (that's why MinimapButton/HostSettings/Cards all fall back to the `ChairfacesCasinoDB` global). Fixed in 2.4.0 via `local ADDON_NAME = ...` vararg matching, but **never assume `BJ.db` is set in a module's `Initialize`** — attach to the global yourself like DebtLedger does.

### Clickable chat links

`BJ:CreateGameLink(game, text)` produces `|Haddon:casinolink:<game>|h[...]|h` links; `SetItemRef` is post-hooked (`hooksecurefunc`) in `Core.lua` to route clicks to the correct UI frame. The `addon` hyperlink type is the one Blizzard ignores natively — never override the `SetItemRef` global (it taints the hyperlink path and breaks protected actions like Copy Character Name with ADDON_ACTION_FORBIDDEN).

## Conventions

- Chat and event text: read it through `BJ:Readable(value)` (plain string, or nil) before indexing, matching or comparing it. On WoW Forever a secret string still answers `type() == "string"` and then throws on the first read ("attempt to index local 'text' (a secret string value)"); in a channel handler, check the channel name first so General/Trade are dropped untouched. Tests: `tests/chat_secret_test.py`.
- Gold formatting: always go through `BJ:FormatGold` / `BJ:FormatGoldColored` / `BJ:FormatGoldSigned` (silver = 0.01g; the signed variant prefixes +/- for net amounts).
- User-visible messages: `BJ:Print`; debug: `BJ:Debug` (gated by `db.settings.debug`). Both also route to the lobby log window.
- New network message types: add to the module's local `MSG` table; keep the serialize/deserialize `|`-delimited format consistent within a game.
- Embedded libraries under `Libs/` are vendored Ace3 + ChatThrottleLib + LibStub; don't edit them.
